🐕 monitoring / watchdog

常驻守护进程设计。Hermes ↔ OpenClaw 互救实战。

⭐⭐ 进阶 🐍 Python 🚀 launchd

📌 何时用

  • ✅ 跑了关键服务（Hermes 网关 / 数据库 / 队列）
  • ✅ launchd KeepAlive 不够（不能救 OOM / JS hang）
  • ✅ 想要"静默优先"（失败才推用户）
  • ❌ 普通 cron（用 cron 模板）
  • ❌ 一次性任务

🚀 设计骨架

# 配置
PEERS = {
    "hermes":   {"launchd": "ai.hermes.gateway", "cli": ["", "status"]},
    "openclaw": {"launchd": "ai.openclaw.gateway", "url": "http://127.0.0.1:18789/health"},
}
INTERVAL = 60        # 秒
THRESHOLD = 5        # 累计失败次数
COOLDOWN = 300       # 重启后冷却（秒）

while True:
    sleep(INTERVAL)
    for name, peer in PEERS.items():
        if in_cooldown(name): continue
        if probe(peer):
            reset_fails(name)
        else:
            fails += 1
            if fails >= THRESHOLD:
                launchctl kickstart -k gui/$UID/<label>
                cooldown(name, COOLDOWN)
                fails = 0

🔑 关键设计

原则理由
用 launchd 拉 watchdog 本身watchdog 死了还能拉起来
用绝对路径调 CLIlaunchd 进程 PATH 不含用户 venv
累计阈值才重启单次失败可能是网络抖动
重启后冷却防止连环重启
成功时完全静默不污染用户通知

  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key>
  <dict>
    <key>SuccessfulExit</key><false/>
    <key>Crashed</key><true/>
  </dict>
</dict>
</plist>
