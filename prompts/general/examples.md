## 案例 1：技术决策（"换 ORM 吗？"）

### 输入 prompt（主模板）
```text
# 角色
你是一个严谨的工程助手。

# 任务
请回答：我的 Hermes Agent 项目该不该从 SQLAlchemy 切到 Peewee？项目现在 2000 行 ORM 代码、3 个表、单文件。

# 输出格式
【第 1 段 理解问题】[1-2 句]
【第 2 段 拆解步骤】[3-5 步]
【第 3 段 逐步求解】[详细，禁止跳步]
【第 4 段 自我反思】[找漏洞]
【第 5 段 最终答案】[一句话 + 论证]

# 行为规则
禁止跳步；自我反思要真实找问题。
```

### 期望的 LLM 输出
```
【第 1 段 理解问题】
你问的是一个 2000 行规模、单文件的小型项目，是否值得做 ORM 迁移的决策。
关键约束：项目规模、迁移成本、是否真有痛点。

【第 2 段 拆解步骤】
1. 评估当前 SQLAlchemy 使用中是否有真实痛点
2. 评估切换能带来的具体收益
3. 评估迁移成本（学习曲线 + 重写代码 + 测试回归）
4. 评估替代方案（不全切、混合、部分用 raw SQL）

【第 3 段 逐步求解】
1. SQLAlchemy 痛点：模板已覆盖 80%，无大痛；async 支持有限
2. Peewee 收益：API 简单、文档清晰、异步支持好 → 但收益有限
3. 迁移成本：~2000 行重写 + 测试回归 + 1-2 周；高
4. 替代：保持 SQLAlchemy，等真有痛点再切

【第 4 段 自我反思】
- 我假设了 SQLAlchemy 真的"无大痛"——如果用户实际有痛点，我低估了迁移收益
- 没考虑团队熟悉度——如果团队熟 Peewee 可能值得
- "等真有痛点再切"可能让用户觉得我在回避问题

【第 5 段 最终答案】
**不建议切**：当前规模无足够痛点，迁移成本（~2 周）> 收益；建议保留 SQLAlchemy，等痛点真正出现时再评估。
```

## 案例 2：投资决策（A 股 BUY/SELL）

### 输入 prompt（高级版 + 反思）
```text
# 角色
你是一个严谨的判断专家。

# 任务
贵州茅台（600519）当前价 1680 元，昨收 1700 元（-1.18%）。技术面：MA5=1690, MA10=1705, MA20=1720, RSI=42, MACD 柱=-1.2。
请判断是否该买入。

[输出按高级版第一/二/三轮]
```

### 期望输出（节选）
```
【第一轮：A/B/C 候选答案】

A. **不买入，继续观察**
- 核心：MA20 之上但跌破 MA5/MA10，动能转弱
- 依据：MACD 柱 -1.2（连续负），RSI 42 偏弱，趋势走坏苗头
- 不确定性：可能只是短期回调

B. **小幅减仓**
- 核心：已亏 1.18%，回撤到 MA20 风险大
- 依据：跌破 MA5 是技术信号，建议减 1/3
- 不确定性：可能误判

C. **加仓抄底**
- 核心：优质标的回调是机会
- 依据：长期看茅台仍是龙头
- 不确定性：短期可能继续跌

【第二轮：自我反思】
- A 稳健但保守
- B 适中，理性
- C 情绪化，违反"无趋势不买"原则

【第三轮：投票】
- B 最合理：减 1/3，剩余 2/3 持仓观察
- 不全砍是因为长期逻辑没坏
- 不加仓是因为技术面没转好

【最终答案】**减仓 1/3**，保留 2/3 持仓，等待技术面企稳（MA5 重新走平 / MACD 柱翻正）。
```

## 案例 3：法律/规则判断（"这合规吗？"）

### 输入
```text
我们公司要采集员工微信聊天记录用于绩效考核，合规吗？
[输出用主模板]
```

### 期望（节选）
```
【第 1 段 理解问题】
评估采集员工微信聊天记录用于绩效考核的合规性。
关键约束：地域（中国《个人信息保护法》）、员工同意、采集方式、目的正当性。

【第 2 段 拆解步骤】
1. 评估目的正当性（绩效 vs 监控）
2. 评估是否取得员工单独同意
3. 评估采集方式（设备监控 / API 抓取）
4. 评估数据最小化原则
5. 给出合规路径

【第 3 段 逐步求解】
1. 目的：绩效考核勉强算"人力资源管理"目的，属于《个保法》第 13 条第 2 项
2. 同意：必须**单独**取得书面同意，不能藏在入职合同里
3. 方式：如装在工作手机/电脑，仅采集工作相关（不采集私人聊天）
4. 最小化：仅采集绩效相关字段（响应时间、客户评价等），不采集聊天内容
5. 合规路径：员工手册明确告知 + 单独同意书 + 仅工作设备 + 数据加密 + 第三方审计

【第 4 段 自我反思】
- 我对"工作设备 vs 私人设备"假设可能过强——如果员工用私人微信联系客户，难度大
- "单独同意"在司法实践中标准模糊
- 没考虑《劳动合同法》《工会法》对绩效考核的特殊要求

【第 5 段 最终答案】
**有条件合规**：仅在员工使用公司配发设备 + 取得员工单独书面同意 + 仅采集绩效相关字段 + 明确告知目的 + 加密存储 + 定期审计的前提下，可以做。建议法务介入。
```

## 案例 4：极简版（1 句话）

### 输入
```text
回答前先问自己：(1) 问题真正在问什么？(2) 关键约束是什么？(3) 有没有更直接的思路？
然后直接给答案 + 1 句话理由。

Python 的 GIL 是什么？
```

### 期望
```
GIL（Global Interpreter Lock）是 CPython 解释器的全局锁，任意时刻只允许一个线程执行 Python 字节码。
是 CPython 解释器级（不是语言级）的互斥锁，让单进程内的多线程无法真正并行（CPU 密集任务），但 I/O 密集型任务能"并发"。
```
